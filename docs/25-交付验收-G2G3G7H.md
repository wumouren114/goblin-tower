## 4. H mute-test ✅ 已接受（补丁后复核）

**它的结论**：`ok=false`，findings 2 条，均为「M 键到达 window 但静音不同步（audio=false, hud=true）」。

**实际复核**：**M 键是好的**。它的 `audioMuted` 来自 `readDebug()`——解析 `#debug-overlay` 的文本，而 main.ts 里该叠层**每 500ms 才重渲染一次**：

```js
// sim/mute-test.mjs
const text = await cdp.eval(`document.querySelector('#debug-overlay')?.textContent ?? ''`)
```

所以按下 M 后立刻读，读到的是 500ms 前的快照 → `audio.muted=false`，而 `hudMuted` 是同步 DOM 读取 → `true`。下一个采样点 `audioMuted` 就变 true 了（它的 step 日志里正好能看到这个顺序）。
→ **两条 findings 都是采样延迟造成的假阳性，不是游戏 bug。**

**返工要求（很小）**：
- 方案 A（推荐）：在 `main.ts` 的 `?debug=1` 分支里挂一个只读句柄，例如 `window.__audio = { status: () => audio.status() }`；测试直接调它取实时值。
- 方案 B：不碰源码，读取叠层后**轮询到值变化或 ≥600ms** 再断言（并把"等待"写进报告，避免下一次又踩）。
- 另外：`ok = findings.length === 0` 这条已经改对了，保持。
